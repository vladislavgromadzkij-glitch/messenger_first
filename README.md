# FIRST_MESSANGER
## Назначение и философия системы

Высокопроизводительный децентрализованный P2P-мессенджер и локальная операционная среда для автономных ИИ-агентов. Архитектура исключает использование централизованных серверов, гарантирует устойчивость к государственной цензуре, аппаратную изоляцию мастер-ключей и объединяет прямое бессерверное общение узлов с глубокой песочницей для ИИ. Пользователь получает полный контроль над системой: от стандартного агрегатора нейросетей по API (Codex, Claude, Google Gemini, локальные модели) до делегирования искусственному интеллекту прав ответов в чатах, сбора аналитики и полного управления ПК через кастомные C++ и Python инструменты.

---

## Архитектурный стек и физика системы

### 1. Модель многопоточности и аппаратная изоляция

* 🟢 **Поток 1: Главный поток GUI (Main Thread / Ring 3 UI & Bridge)**:


* Обеспечивает аппаратную синхронизацию VSync (60/144 FPS) без просадок кадровой частоты.


* Рендерит сцену QML Scene Graph и обрабатывает оконные прерывания кастомного Frameless-окна через `DragHandler` и нативный вызов `root.startSystemMove()`.


* **Служба `SettingsManager**`: Выделена строго в Потоке 1 как легковесный бескомпромиссный маршрутизатор памяти (`Bridge`). Она принимает вызовы из JavaScript-песочницы V4 через `Q_INVOKABLE` со сложностью $O(1)$, не блокируя графический конвейер, и передает тяжелые задачи дальше через шину мета-объектов `Qt::QueuedConnection`.




* 🟢 **Поток 2: Фоновый дисковый и криптографический воркер (`ioThread` / Crypto & Storage)**:


* Полностью изолирован от контекста GUI вызовом `cryptoVault->moveToThread(ioThread)`.


* Исполняет блокирующие системные вызовы ввода-вывода (VFS), сканирует дисковые секторы, читает профили и производит аппаратное дешифрование через `CryptoVault`.


* 🟡 **Криптографическая вилка (Disaster Recovery)**: На этапе регистрации Поток 1 сбрасывает DTO-структуру в Поток 2, где `CryptoVault` генерирует два изолированных контейнера: основной в защищенном каталоге ОС и резервный со своей солью, вектором инициализации и дампом мастер-ключа по внешнему пути `m_pendingBackupPath`.




* 🔴 **Потоки 3+: Network Dispatcher & Worker Pool (Сетевой стек и расчеты)**:


* Сетевой слушатель на аппаратных прерываниях ядра: системный вызов `epoll` (Linux) / `IOCP` (Windows). Поток засыпает с нулевым потреблением CPU (0.0%), пока сетевая карта не сгенерирует прерывание IRQ по шине PCIe при получении зашифрованного пакета.


* Lock-Free очереди: Обмен пакетами между сетевым потоком и пулом рабочих ядер процессора строится на кольцевых буферах без мьютексов (атомарные инструкции Compare-And-Swap), исключая взаимные блокировки потоков (Deadlocks).

### 2. Низкоуровневая память и физика файловой системы

* 🟢 **Бинарная инкапсуляция (.rodata cache)**: Полный отказ от хранения конфигураций по умолчанию (`default_ui.json`) на жестком диске. Базовые матрицы палитры (`coreVisual`), типографики (`coreTypography`) и сеток (`advancedConfig`) вшиты в бинарный образ (`.rodata`). При отсутствии профилей движок читает их из кэша L1 процессора за 0 тактов ввода-вывода.


* 🟢 **POD-структуры и блочное выравнивание**: Заголовок профиля `AccountPrimaryHeader` упакован директивой `#pragma pack(push, 1)`. Поля структурированы фиксированными длинами (хеши 32 байта, соли 16 байт, временные метки 8 байт), дополнены 13 байтами `trashedData` для плотного блочного чтения кэш-линиями процессоров архитектур x86-64 и ARM.


* 🟢 **DSE-устойчивое выжигание ОЗУ**: При уничтожении объектов и завершении работы память ключей затирается через `OPENSSL_cleanse` и метод `secureWipeString`, предотвращая оптимизацию компилятора Dead Store Elimination и утечку векторов через дамп ядра.


* 🔴 **Zero-Copy Memory-Mapped Files (`mmap`)**: База сообщений `history.mmap` проецируется напрямую в виртуальное адресное пространство процесса системным вызовом `mmap`. Выборка истории происходит аппаратно через DMA-контроллер и Page Fault со скоростью шины ОЗУ, минуя двойную буферизацию в пространстве ядра.


* 🔴 **Zero-Copy передача медиафайлов**: Скачивание и отдача тяжелых файлов реализуется системным вызовом ядра Linux `splice()`, перенаправляющим поток байт напрямую из буфера сетевой карты в файловый дескриптор SSD без копирования в ОЗУ приложения.

### 3. Криптографическое ядро и связки ключей

* 🟢 **Аппаратный AES-256-GCM**: Симметричное шифрование блоков данных профиля и сообщений с контролем аутентичности (Tag 16 байт, IV 12 байт) через OpenSSL EVP API с поддержкой аппаратных процессорных инструкций AES-NI и ARM CE.


* 🟢 **Аппаратная изоляция мастер-ключа ОС**: Реализована автоматическая генерация и извлечение 32-байтного мастер-ключа из доверенных системных хранилищ:
* Linux: `libsecret` (интерфейс Linux Secret Service по системной шине D-Bus).


* macOS: Apple Keychain API (`SecItemCopyMatching` / `SecItemAdd`).


* Windows: Windows Credential Manager (`CredReadW` / `CredWriteW`).




* 🔴 **KDF «В покое» (Argon2id)**: Деривация ключей из паролей и PIN-кодов с жестким выделением непоследовательных блоков памяти в ОЗУ, делающая перебор через GPU и ASIC аппаратно невозможным.



---

### 4. P2P-сеть, децентрализация и криптографическая карма

* 🔴 **Kademlia DHT (XOR-маршрутизация)**: Поиск пиров и маршрутизация сетевых пакетов в глобальной сети без серверов путем расчета расстояния между 256-битными хешами узлов операцией `XOR`. Локальный поиск в пределах подсети использует UDP Broadcast/Multicast.


* 🔴 **Merkle DAG (Ациклический граф истории)**: Каждое отправленное сообщение содержит хеш SHA-256 предыдущего блока и цифровую подпись Ed25519/ECDSA. Любая попытка подмены или удаления истории третьей стороной ломает граф и аппаратно отвергается валидатором ядра.


* 🔴 **Web of Trust (Система кармы и репутации)**: Защита от спама и атак Сивиллы. Узлы обмениваются криптографическими печатями доверия при взаимной верификации открытых ключей. Сообщения от неизвестных узлов с нулевой кармой блокируются по медиа-контенту и маркируются предупреждающим цветом.


* 🔴 **Proof-of-Work (Hashcash спам-фильтр)**: Чтобы отправить сообщение в сеть, CPU отправителя обязан решить криптографическую задачу подбора Nonce (0.3 с нагрузки на ядро процессора), делая массовый спам экономически невозможным.


* 🔴 **Mesh-сети (BLE, Wi-Fi Aware, LoRa)**: Устойчивость к полному отключению интернета. Передача пакетов от узла к узлу (Sneakernet) через профили BLE GATT, Wi-Fi Aware и радиомодули LoRa CSS на дистанции до 15 км.


* 🔴 **DPI-маскировка**: Добавление энтропийного пэддинга (случайных байт) для выравнивания сетевых пакетов под паттерны WebRTC и HTTPS-видеопотоков.

### 5. Аппаратный графический конвейер (Scene Graph)

* 🟢 **Theme Orbital Green**: Контрастная палитра для исключения утомляемости глаз: глубокий вакуумный фон `#0B0F19` (минимальная эмиссия пикселей), панели `#161D2B`, изумрудный акцент `#10B981` и стальной `#64748B`.


* 🟢 **Telegram-style Frameless Header**: Минималистичная панель управления окном (высота 32px), сливающаяся с окном. Кнопки «Свернуть», «Развернуть», «Закрыть» скрыты и подсвечиваются мягким свечением только при наведении (`hoverEnabled: true`): мятным `#34D399`, банановым `#FBBF24` и малиновым `#FB7185`.


* 🟢 **Стейт-машина прерываний валидации**: Защита UI от зависаний. Блокировка кнопки «Проверить директорию» флагом `isChecking`, очистка ошибок и вывод системных отказов (EACCES, ENOENT) красным цветом `#EF4444` без остановки рендеринга.


* 🔴 **Zero-Overhead Текстурные Атласы**: Рендеринг шрифтов Inter и JetBrains Mono через предрастеризованные библиотекой FreeType атласы в видеопамяти (VRAM). Переключение жирности (`isMainBold`) меняет указатель на атлас за 1 такт процессора без повторного парсинга кривых Безье.

### 6. Архитектура ИИ-Агрегатора и локального Агента

* 🟡 **Универсальный шлюз нейросетей (API & Cloud)**:
* Прямая интеграция внешних провайдеров по стандартизированным API: Anthropic (протокол Claude / Claude Code), OpenAI (Codex / GPT-4o / o-серия), Google Gemini API, а также совместимость с открытыми моделями (DeepSeek, Qwen).
* Встроенное веб-пространство (Web Sandbox Sidebar) для прямого взаимодействия с аккаунтами нейросетей без расхода API-токенов (по аналогии с боковыми панелями браузеров).


* 🟡 **ИИ как полноправный участник чатов**:
* Сессии ИИ отображаются как обычные диалоги в едином списке чатов в стиле Telegram на базе виртуализированных моделей `ChatViewModel`.


* Возможность создания множества независимых агентов с разными системными промптами, температурами и моделями под разные задачи.


* 🔴 **Локальный инференс (Local Privacy Core)**:
* Прямое подключение локальных движков инференса без выхода в сеть: `llama.cpp` (C++ бэкенд с поддержкой Vulkan/ROCm/CUDA), Ollama и vLLM.


* 🔴 **Гранулярная матрица разрешений (Zero-Trust AI Sandbox)**:
* *Уровень 1 (Изолированный ассистент)*: Модель видит только контекст сообщений в своей личной вкладке диалога.
* *Уровень 2 (Аналитик контекста)*: Пользователь явно выдает агенту право на чтение выбранного чата, группы или канала. Модель на лету вычитывает историю из `history.mmap`, строит саммаризацию, извлекает задачи и собирает статистику.


* *Уровень 3 (Автономный секретарь / Автоответчик)*: Модель получает доступ на генерацию и отправку сообщений собеседникам за пользователя. Срабатывает по триггерам, расписанию или правилам системного промпта.
* *Уровень 4 (System Controller / Полный доступ к ПК)*: Модели делегируются права на выполнение системных команд ОС, манипуляцию файлами, сборку кода и управление процессами.


* 🔴 **Кастомная экосистема локальных инструментов (Tool Calling)**:
* Возможность написания собственных тулов на Python (через скриптовый мост) и C++ (в виде динамических библиотек `.so` / `.dll`).
* Аппаратный перехват и логирование вызовов тулов для предотвращения деструктивных действий агента в системе.

## Требования к среде

* **Операционная система**: Linux (проверено на Fedora 43 / Ubuntu 22.04+), macOS 13+, Windows 10/11.


* **Среда сборки C++**: CMake 3.16+, компилятор с поддержкой стандарта C++17 / C++20 (GCC 11+, Clang 14+, MSVC 2022).


* **Фреймворк**: Qt 6.8+ (модули `Quick`, `Core`, `Gui`, `Qml`).


* **Системные криптобиблиотеки**:
* OpenSSL 3.x (`libcrypto`, `libssl`).


* `libsecret-1` и `glib-2.0` (для сборок под Linux).




* **Интерпретатор Python**: Python 3.10+ (для локальных инструментов, скриптов автоматизации и агентов).


* **Контроль версий**: Git с настроенным доступом к репозиторию.

## Получение проекта

Выполни клонирование репозитория в чистую рабочую директорию. Замени `ССЫЛКА_НА_РЕПОЗИТОРИЙ` на актуальный HTTPS-адрес без токенов и паролей:

```bash
git clone "ССЫЛКА_НА_РЕПОЗИТОРИЙ" p2p-messenger
cd p2p-messenger

```

Папка `p2p-messenger` должна быть новой. Открой её в редакторе (VS Code: File → Open Folder) и открой новый терминал. Повторные `git init` и настройка `origin` не требуются.

## Подготовка и запуск

Все команды выполняются из корня репозитория `p2p-messenger`.

### 1. Настройка окружения ИИ-агентов (Python)

Для работы локальных тулов и скриптов автоматизации создай виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate

```

Установи базовые зависимости:

```bash
python -m pip install -r requirements.txt

```

Создай локальный файл переменных окружения:

```bash
cp .env.example .env

```

Заполни параметры в созданном файле `.env`:

* `MODEL`: идентификатор модели (`claude-3-7-sonnet`, `gemini-2.5-pro`, `gpt-4o`, `qwen2.5-coder`).
* `BASE_URL`: эндпоинт API (OpenAI/Anthropic/Google совместимый адрес или локальный сервер Ollama/vLLM).
* `API_KEY`: персональный API-ключ авторизации.



### 2. Сборка C++ Ядра через CMake

Собери бинарный исполняемый файл приложения:

```bash
mkdir -p build && cd build
cmake ..
cmake --build . -j$(nproc)

```

### 3. Запуск приложения

Запусти скомпилированный бинарник:

```bash
./appfirst

```

## Ожидаемый результат работы ядра

1. 🟢 Приложение запускается в безрамочном окне 1600x900 с космической палитрой и аппаратным drag-контроллером.


2. 🟢 Служба `SettingsManager` инициализирует `loadSettings()`, сканируя директорию `profiles`.


3. 🟢 При отсутствии профилей ядро генерирует сигнал `fallbackRequested()`, и `StackView` рендерит компонент `backupPathScreen`.


4. 🟢 Пользователь указывает путь к изолированной директории вручную или через диалог «Обзор ОС».


5. 🟢 При нажатии кнопки «Проверить директорию» интерфейс блокируется (`isChecking = true`), исключая повторные прерывания.


6. 🟢 **Успех**: C++ ядро проверяет права через `access(W_OK)`, сохраняет путь в `m_pendingBackupPath`, выстреливает `backupPathValid()`, и QML переключает сцену на заглушку `registrationFormScreen`.


7. 🟢 **Отказ**: При отсутствии прав или несуществующем каталоге C++ отправляет сигнал `backupPathInvalid(reason)`, интерфейс оживает и выводит красный текст ошибки `#EF4444`.

## Дорожная карта развития (Roadmap)

### Спринт 1: Финализация регистрации и Cryptographic Fork

* 🟡 **QML Анкета регистрации**: Поля ввода `username`, `password`, подтверждения, `pin`, чекбокс режима валидирующей ноды.
* 🟡 **Single-Shot DTO Payload**: Упаковка всей анкеты в структуру `ProfilePayload` и отправка одним системным вызовом `Q_INVOKABLE` в Поток 1 без микрофризов MOC-шины.
* 🟡 **Генерация криптографической вилки в Потоке 2 (`ioThread`)**:
* Создание мастер-ключа и шифрование основного профиля в системном каталоге ОС.


* Генерация независимой соли/IV, деривация резервного ключа через Argon2id от PIN-кода и сборка резервного контейнера аварийного восстановления в `m_pendingBackupPath`.





### Спринт 2: Список чатов (Telegram-стандарт) и UI Агрегатора

* 🟡 **Двухпанельный лейаут**: Левый сайдбар со списком чатов и правая рабочая область сообщений.


* 🟡 **Интерфейсные модели C++**: Подключение `ChatViewModel` и `ContactsModel` с пагинацией и виртуализацией списков для плавного скролла при 100 000+ диалогов.


* 🟡 **Интеграция ИИ в общий список**: Отображение диалогов с нейросетями в общем списке чатов наравне с обычными пользователями.
* 🟡 **Шлюз облачных LLM**: Подключение API OpenAI, Anthropic, Google Gemini и браузерного бокового интерфейса.

### Спринт 3: Локальные модели, тулы и гранулярная матрица прав

* 🔴 **Локальный инференс**: Встраивание бэкенда `llama.cpp` для полностью офлайн-работы нейросетей на мощностях локального GPU.
* 🔴 **Система уровней доступа (Level 1–4)**: Разграничение прав ИИ (от изоляции до чтения истории `history.mmap`, автоответов и полного управления ПК).


* 🔴 **Среда выполнения тулов**: Запуск скриптов на Python и библиотек на C++ с перехватом системных вызовов.

### Спринт 4: Децентрализованный сетевой стек

* 🔴 **P2P Core**: Развертывание Kademlia DHT на базе `epoll`/IOCP.


* 🔴 **Merkle DAG & Web of Trust**: Криптографические цепочки сообщений, подписи доверия и карма пиров.


* 🔴 **Mesh & Anti-Censorship**: Режим работы по BLE/LoRa и маскировка пакетов под WebRTC.

## Если окружение не активируется

Если `.venv` блокируется политиками ОС или не активируется через `source`, используй бинарники виртуального окружения напрямую:

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py

```

Если сборка C++ падает из-за отсутствия системных криптобиблиотек, установи пакеты разработчика:

```bash
# Fedora
sudo dnf install libsecret-devel openssl-devel qt6-qtbase-devel qt6-qtdeclarative-devel

# Ubuntu/Debian
sudo apt-get install libsecret-1-dev libssl-dev qt6-base-dev qt6-declarative-dev

```
