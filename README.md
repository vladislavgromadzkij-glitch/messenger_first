# Nexus P2P & Autonomous AI Mesh Core

## Назначение

Децентрализованный, высокопроизводительный P2P-мессенджер и локальная операционная среда для автономных ИИ-агентов. Архитектура исключает использование централизованных серверов, гарантирует устойчивость к цензуре, аппаратную защиту криптографических ключей и объединяет прямое общение узлов с гранулярным управлением ИИ-ассистентами (от интеграции облачных LLM через API до выполнения локальных инструментов на C++ и Python с возможностью полной автоматизации системы).

---

## Архитектурный стек и спецификация

### 1. Низкоуровневое хранилище и физика памяти

* **Бинарная инкапсуляция:** Базовые визуальные матрицы (`coreVisual`, `coreTypography`, `advancedConfig`) вшиты непосредственно в бинарный образ (`.rodata`), исключая системные вызовы `open()`/`read()` к диску при отсутствии профиля и загружаясь в кэш L1 за 0 тактов ввода-вывода.


* **Zero-Copy Memory-Mapped Files (`mmap`):** Локальная база переписок (`history.mmap`) проецируется напрямую в виртуальное адресное пространство процесса (системный вызов `mmap` в Linux / `CreateFileMapping` в Windows). Чтение страниц осуществляется аппаратно контроллером памяти через DMA и Page Fault, минуя промежуточную буферизацию ядра.


* **Изоляция структур данных (POD):** Структура профиля `AccountPrimaryHeader` упакована с побайтовым выравниванием (`#pragma pack(push, 1)`), содержит бинарные поля для ключей, солей и хешей, а также дополняющие байты (`trashedData`) для оптимизации блочного чтения процессорами x86/ARM.


* **Безопасная очистка RAM:** При деструкции объектов и завершении сессий критические участки памяти затираются нулями через `OPENSSL_cleanse` и `secureWipeString` для защиты от DSE (Dead Store Elimination) и анализа дампов памяти ядра.



### 2. Криптографическое ядро и модель «Cryptographic Fork»

* **Аппаратное шифрование:** Симметричное шифрование профилей и сетевых пакетов выполнено на базе AES-256-GCM с контролем целостности (Auth Tag 16 байт, IV 12 байт) через OpenSSL EVP API с поддержкой аппаратных инструкций AES-NI и ARM CE.


* **Аппаратные связки ключей ОС:** Мастер-ключ устройства (`CryptoVault_DeviceKey`) изолирован в нативных защищенных хранилищах: `libsecret` (Linux Secret Service через D-Bus), Apple Keychain (`SecItemAdd`) и Windows Credential Manager (`CredWriteW`).


* **Криптографическая вилка (Disaster Recovery):** Генерация двух независимых криптоконтейнеров:
* *Основной контейнер:* Зашифрован мастер-ключом ОС с привязкой к конкретному оборудованию.


* *Резервный контейнер:* Размещается по изолированному пути (`m_pendingBackupPath`), шифруется вторичным ключом (деривация через Argon2id от PIN-кода/пароля со своей солью и IV) и содержит резервный дамп мастер-ключа для восстановления в случае сбоя или переустановки ОС.





### 3. P2P-сеть, репутация и транспортный уровень

* **Kademlia DHT (XOR-метрика):** Маршрутизация и поиск узлов в глобальной сети без серверов через вычисление расстояния XOR между 256-битными хешами узлов. Локальное обнаружение использует UDP-мультикаст.


* **Криптографическая цепь истории (Merkle DAG):** Сообщения связываются через хеши предыдущих записей (SHA-256) и подписываются приватным ключом (Ed25519/ECDSA), формируя защищенный направленный ациклический граф, исключающий незаметную подмену истории.


* **Система доверия (Web of Trust) и защита от Сивиллы:** Рейтинг и карма узлов определяются криптографическими «печатями доверия», создаваемыми при взаимном сканировании публичных ключей. Узлы без подтвержденного доверия ограничиваются в отправке медиаданных и маркируются как потенциально опасные.


* **Proof-of-Work (Hashcash):** Защита от спама и DDoS-атак требует вычисления короткого PoW на базе SHA-256 (~0.3 с работы CPU на сообщение), что делает массовую генерацию пакетов экономически невозможной.


* **Zero-Copy передача файлов:** Перекачка больших файлов использует системный вызов `splice()` ядра Linux для передачи данных напрямую из кольцевого буфера сетевой карты в файловый дескриптор диска без задействования оперативной памяти приложения.


* **Mesh-сети и устойчивость к блэкаутам:** При разрыве TCP/IP-соединений транспортный уровень переключается на Bluetooth Low Energy (BLE GATT), Wi-Fi Aware и модули LoRa (Chirp Spread Spectrum), передавая пакеты по цепочке соседних устройств.


* **Обход DPI:** Выравнивание энтропии и добавление мусорных байт (padding) маскируют P2P-трафик под потоки WebRTC или стриминговых платформ.



### 4. Модель многопоточности и изоляция UI

* **Главный поток (GUI/Ring 3):** Обеспечивает плавность 60/144 FPS VSync, управляет сценой QML Scene Graph и окном без рамок (Frameless Window) с системным перехватом курсора через `DragHandler` и `startSystemMove()`.


* **Мост маршрутизации (`SettingsManager`):** Живет в главном потоке, мгновенно принимает системные прерывания от QML (`Q_INVOKABLE`) и транслирует команды в фоновые воркеры через безопасную мета-систему сигналов Qt (`Qt::QueuedConnection`).


* **Фоновый поток ввода-вывода (`ioThread` / `CryptoVault`):** Изолирован от GUI через `moveToThread(ioThread)`, выполняет блокирующие дисковые операции, чтение хранилищ и аппаратное дешифрование данных.

## Требования

* **Операционная система:** Linux (проверено на Fedora 43 / Ubuntu 22.04+), macOS 13+, Windows 10/11.


* **Среда сборки C++:** CMake 3.16+, компилятор с поддержкой стандарта C++17 / C++20 (GCC 11+, Clang 14+, MSVC 2022).


* **Фреймворк:** Qt 6.8+ (модули `Quick`, `Core`, `Gui`, `Qml`).


* **Системные криптобиблиотеки:**
* OpenSSL 3.x (`libcrypto`, `libssl`).


* `libsecret-1` и `glib-2.0` (для сборок под Linux).




* **Интерпретатор Python:** Python 3.10+ (для локальных инструментов, скриптов автоматизации и обвязок LLM).


* **Контроль версий:** Git с настроенным доступом к репозиторию.

## Получение проекта

Выполни клонирование репозитория в чистую рабочую директорию. Замени `ССЫЛКА_НА_РЕПОЗИТОРИЙ` на актуальный HTTPS-адрес без токенов и паролей:

```bash
git clone "ССЫЛКА_НА_РЕПОЗИТОРИЙ" p2p-messenger
cd p2p-messenger

```

Открой созданную папку в редакторе (например, VS Code: File → Open Folder) и запускай встроенный терминал. Повторная инициализация Git не требуется.

## Подготовка и запуск

Все команды выполняются из корня репозитория `p2p-messenger`.

### 1. Настройка окружения инструментов ИИ (Python)

Для работы локальных кастомных агентов и тулов создай изолированное виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate

```

Установи зависимости для интеграции ИИ-моделей:

```bash
python -m pip install -r requirements.txt

```

Создай локальный файл переменных окружения:

```bash
cp .env.example .env

```

Заполни параметры в созданном файле `.env`:

* `MODEL`: идентификатор модели (например, `claude-3-7-sonnet`, `gemini-2.5-pro`, `gpt-4o` или локальная `qwen2.5-coder`).
* `BASE_URL`: базовый эндпоинт API (OpenAI/Anthropic/Google совместимый адрес или локальный сервер vLLM/Ollama).
* `API_KEY`: персональный API-ключ для авторизации в сервисе LLM.



### 2. Сборка C++ Ядра через CMake

Собери бинарный исполняемый файл приложения:

```bash
mkdir -p build && cd build
cmake ..
cmake --build . -j$(nproc)

```

### 3. Запуск приложения

Запусти собранный бинарник из папки сборки:

```bash
./appfirst

```

## Текущий статус реализации (Готово на данный момент)

1. **Frameless UI & Орбитальный дизайн:**
* Реализован кастомный оконный менеджер с интеграцией в графический сервер через `DragHandler` и `root.startSystemMove()`.


* Внедрены адаптивные элементы управления окном (свернуть, развернуть, закрыть) в стиле Telegram с аппаратными эффектами наведения (`hoverEnabled`, подсветка мятным `#34D399`, банановым `#FBBF24` и малиновым `#FB7185`).


* Развернута контрастная палитра `theme_orbital_green` (`#0B0F19` глубокий вакуум, `#161D2B` панели, `#10B981` изумрудная телеметрия) для снижения утомляемости глаз.




2. **Архитектура изоляции потоков (Main Bridge):**
* Объект `SettingsManager` закреплен в главном потоке для безопасного обмена данными со сценой QML, предотвращая сбои `Illegal attempt to connect`.


* Объект `CryptoVault` перенесен в поток `ioThread` и соединен через кросс-поточные сигналы Qt MOC.




3. **Системная верификация директорий:**
* Реализован синхронный метод проверки файловой системы `SettingsManager::verifyBackupPath` с валидацией существования (`exists`), абсолютности пути (`isAbsolute`) и системных прав на запись (`isWritable` / `access`).


* Проверенный путь сохраняется в оперативной памяти (`m_pendingBackupPath`) для последующего использования при создании профиля.




4. **Аппаратный криптографический анализ профилей:**
* Написан алгоритм автоматического извлечения/генерации мастер-ключа ОС через `libsecret` с затиранием мусора в памяти.


* Реализовано пакетное сканирование существующих профилей, безопасное чтение заголовков `AccountPrimaryHeader` и аппаратная валидация через AES-256-GCM с проверкой тега подлинности.

## Ожидаемый результат

1. При запуске открывается главное окно 1600x900 без рамок ОС.


2. При отсутствии существующих профилей ядро переходит в режим Fallback, вызывая отображение компонента `backupPathScreen`.


3. В поле ввода пути вводится абсолютный каталог (например, `/home/user/secure_drive`) вручную или через диалог «Обзор ОС».


4. Нажатие кнопки «Проверить директорию» вызывает временную аппаратную блокировку кнопки (`isChecking = true`).


5. **Успешный результат:** При наличии прав записи C++ генерирует сигнал `backupPathValid()`, интерфейс переключает экран `windowStack` на капсулу с текстом `SUCCESSFUL: Переход к анкете`.


6. **Отказ:** При некорректном пути или отсутствии прав ядро возвращает `backupPathInvalid(reason)`, интерфейс разблокирует кнопку и выводит текст ошибки красным цветом (`#EF4444`).

## Дорожная карта развития (Roadmap)

### Этап 1. Завершение регистрации и Cryptographic Fork (Ближайшая задача)

* Разработка QML-формы ввода реквизитов (имя пользователя, пароль, подтверждение, PIN-код, флаг ноды).
* Упаковка анкеты в единую легковесную структуру `ProfilePayload` (DTO) и отправка в C++ одним вызовом `Q_INVOKABLE` без промежуточных переключений контекста.
* Реализация разделения ключей в `CryptoVault`:
* Создание основного профиля в защищенной системной папке с шифрованием мастер-ключом ОС.


* Создание изолированного файла восстановления по пути `m_pendingBackupPath` со своей солью, вектором инициализации и зашифрованным мастер-ключом.





### Этап 2. Списки чатов и организация рабочей среды (Telegram-стандарт)

* Создание двухуровневого интерфейса: вертикальный список активных диалогов слева и область текущей переписки по центру/справа.


* Подключение списков через виртуальные модели C++ (`ChatViewModel`, `ContactsModel`) с пагинацией и динамическим переиспользованием элементов в памяти (Object Pooling) для гарантии 60 FPS при прокрутке тысяч диалогов.


* Отображение агрегированных ИИ-чатов в общем списке диалогов наравне с P2P-собеседниками.

### Этап 3. Архитектура встроенного ИИ-Агрегатора и агентской среды

* **Мультипровайдерный шлюз:**
* Прямое подключение к провайдерам по API: Anthropic (Claude / Claude Code протокол), OpenAI (Codex / GPT), Google (Gemini API) и локальным сервисам (Ollama, vLLM, llama.cpp).
* Поддержка встроенного бокового веб-окружения для взаимодействия с веб-аккаунтами ИИ (по аналогии с сайдбаром в браузерах).


* **Гранулярная матрица разрешений (Zero-Trust AI Sandbox):**
* *Level 1 (Изолированный ассистент):* Модель видит только сообщения, отправленные непосредственно в чат с ней.
* *Level 2 (Аналитик контекста):* Пользователь явно выдает доступ к чтению выбранной переписки, группы или канала. Модель строит суммаризацию, анализирует статистику и извлекает факты из истории `history.mmap`.


* *Level 3 (Автономный секретарь):* Модель получает право генерировать и отправлять ответы собеседникам от имени пользователя по заданному системному промпту и правилам триггеров.
* *Level 4 (System Controller / Full PC Access):* Модель получает доступ к выполнению локальных команд операционной системы и вызову внешних скриптов.


* **Кастомные локальные тулы (Extensible Tool Ecosystem):**
* Возможность добавления пользовательских расширений (Tool Calling / Function Calling) на C++ (через динамические библиотеки `.so`/`.dll`) и Python.
* Исполнение кода тулов в контролируемой среде с логированием системных вызовов.



### Этап 4. Полномасштабный P2P-стек и децентрализация

* Интеграция сетевого диспетчера на базе `epoll`/IOCP с обработкой сокетов по прерываниям.


* Запуск узлов Kademlia DHT, валидация цепочек Merkle DAG и развертывание протоколов Mesh-сетей (BLE/Wi-Fi Aware).

## Если окружение не активируется

Если виртуальное окружение `.venv` блокируется системной политикой или не активируется через `source`, используй бинарники окружения напрямую:

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest

```

При возникновении ошибок доступа к шине D-Bus при компиляции или запуске под Linux убедись, что служба `dbus` активна, и пакет `libsecret-1-dev` (Debian/Ubuntu) или `libsecret-devel` (Fedora) корректно установлен в системе:

```bash
# Fedora
sudo dnf install libsecret-devel openssl-devel qt6-qtbase-devel qt6-qtdeclarative-devel

# Ubuntu/Debian
sudo apt-get install libsecret-1-dev libssl-dev qt6-base-dev qt6-declarative-dev

```
